# myVita — Phase 6 UAT Plan

Scope: acceptance testing of the myVita web application before any controlled clinical pilot.
All data is synthetic. No real patient, clinic or credential is used. This plan describes what
was tested, how, and what it does **not** prove.

## Environment

| Item | Value |
| --- | --- |
| Topology | Production Compose files (`docker-compose.prod.yml` + `docker-compose.prod-http.yml`), project `myvita-uat`, on a developer workstation |
| Services | PostgreSQL, migrate job, backend (uvicorn, 1 worker), frontend (nginx), proxy (nginx), backup (cron + `pg_dump`) |
| Transport | Plain HTTP on `localhost:18083` (no TLS, no real domain). TLS is untested here |
| Data | Two synthetic clinics (A and B), 4 staff roles, several patients, generated by `backend/scripts/seed_staging.py` |
| Browser | Chromium via Playwright; phone (375 px) and tablet (768 px) viewports for layout |
| Not an environment | This is **not** a staging server. No staging or production environment exists yet |

## Method

- One automated Playwright test per scenario in `frontend/e2e/uat.spec.ts` (22 scenarios), mixing real
  browser flows with direct API calls where the browser cannot express the check (cross-tenant IDs,
  malformed payloads, concurrency).
- Accessibility: `@axe-core/playwright`, WCAG 2.0 A/AA rules, fails on `serious` or `critical`.
  Axe covers a subset of WCAG; it replaces neither a manual keyboard/screen-reader review nor an expert audit.
- Load/concurrency: ad-hoc Node script against the same stack (results in `PHASE6_REPORT.md`).
- Audit evidence: SQL read of `audit_logs` after the run.
- Restart and backup: container restarts; backup, integrity check and restore into a scratch database.
- Backend regression: `pytest` (179 tests), `ruff`, `mypy`, Alembic up/down/up and `alembic check`, `pip-audit`.
- Frontend regression: `tsc -b`, `oxlint`, Vitest (74 tests), production build, `npm audit`.

## Roles exercised

patient, doctor, nurse, administrative staff, clinic admin; a second clinic for isolation checks.

## Entry criteria

- Stack healthy (`/ready` 200, all containers healthy), migrations at head `f6a7b8c9d0e1`.
- Seed data present for both clinics.
- Login rate limit (10/min per IP) respected by the harness (throttled to 6/min).

## Exit criteria

- All 22 scenarios pass on the final build.
- No open defect of severity High or above that is not explicitly accepted by a named owner.
- Regression suites green.
- Remaining risks written down in `DEFECT_REGISTER.md` and `PILOT_READINESS_CHECKLIST.md`.

## Out of scope / not verified

- Real staging/production hosting, public DNS, TLS issuance and renewal.
- Off-site backup to real object storage; alert delivery to real receivers.
- MFA and self-service password recovery (not implemented).
- Legal/DPO approvals, contracts, data-processing agreements, clinical safety sign-off.
- Penetration testing by a third party; load beyond the single-host burst described in the report.
- Native screen-reader testing, other browsers (Firefox, Safari), real mobile devices.
- Users who are not the engineering team: no clinician has used the system yet.
